STEP 4 — Create POM
------------------------
Act as a QA Automation Engineer.

Read these files:

test-plan/login-test-plan.md
test-cases/login-test-cases.md
test-data/login-test-data.js

Create a NEW file:

pages/LoginPage.js

Use the Page Object Model (POM) design pattern.

IMPORTANT:

Keep the locators separate from the action methods.

Do NOT use JavaScript getter methods such as:

get username()
get password()
get loginButton()

Instead, create a dedicated locator object inside the LoginPage class.

Use this structure:

this.locators = {
username: '...',
password: '...',
loginButton: '...'
};

All Login page locators must be stored inside this `locators` object.

The action methods should use the locator object.

For example:

async enterUsername(username) {
await this.page.locator(this.locators.username).fill(username);
}

Create simple methods for:

1. Navigate to Login page
2. Enter username
3. Enter password
4. Click Login
5. Perform Login
6. Logout if required

Keep the implementation simple and beginner-friendly.

Use CSS locators where appropriate.

Do not put locators inside login.spec.js.

Do not create any test cases.

Do not create another locator file.

Do not create Playwright tests yet.

The final LoginPage.js should clearly demonstrate:

Locator Object
↓
Action Methods
↓
Test Script uses Page Object
